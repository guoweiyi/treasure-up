# Treasure Up v0.3.2

本版打通 GitHub 标签发版、双架构 Docker 镜像与客户端安装包的自动发布。应用仍为技术预览。

## Docker 部署

下载 `treasure-up-v0.3.2-docker.zip` 并解压，然后执行：

```bash
python deploy/start.py --prebuilt
# 资源有限时：
python deploy/start.py --prebuilt --light
```

需要 Python 3.10+ 和 Docker Compose v2。发布包只包含部署文件，不需要本地编译；默认镜像固定为本次构建验证过的 OCI 摘要。保留原 `.env` 与数据卷升级。GHCR 首次创建的包默认私有：所有者设为 Public 后可免登录拉取，否则先执行 `docker login ghcr.io`。不要把注册表密码写入 Compose 或仓库。

- 后端：`ghcr.io/guoweiyi/treasure-up-backend:0.3.2`
- 网页：`ghcr.io/guoweiyi/treasure-up-web:0.3.2`
- 两个镜像均含 `linux/amd64` 和 `linux/arm64`，架构由 Docker 自动选择。
- `release-images.json` 保存实际镜像摘要、源码提交及构建来源；`SHA256SUMS` 校验所有发布附件。

## 发布与客户端

- 推送版本标签，或在 Actions 的 Release 页面输入已存在的标签，即自动运行应用回归、依赖审计、原生构建、容器运行测试、安装包与部署包发布。
- 每种容器架构使用原生 runner 构建并运行 PostgreSQL 回归，推送的是经过测试的同一份镜像。版本标签拒绝覆盖不同摘要；预览版更新 `preview`，稳定版才更新 `latest`，旧版本不能把通道倒退。
- Windows x64、macOS ARM64 / x64、Android ARM64 调试 APK、iOS ARM64 模拟器包继续随同发布。源代码和油猴脚本也在附件中。
- 原生 Rust 依赖缓存按平台隔离，PR 不写发布缓存。Android 调试包移除 Rust 调试符号，并检查打包产物中的 ELF 节与体积。
- 所有作业读取同一个不可变提交，候选镜像记录必须匹配本次运行、版本和提交。失败不会公开不完整 Release。

## 边界

Android 仍使用调试签名，不是长期分发签名；不同构建的调试签名可能不同，不承诺覆盖安装。Windows 未商业签名，macOS 未公证；iOS 附件不能安装到 iPhone/iPad，真机与商店分发仍需开发者证书及 provisioning profile。流水线不存放任何私人签名密钥。

本次采用构建后本地加载、完整运行测试、再推送的流程，明确关闭不被该导出路径保留的 BuildKit provenance；镜像清单与 SHA-256 不等同于代码签名。本版未添加自动更新器，也不会自动升级用户正在运行的容器。
