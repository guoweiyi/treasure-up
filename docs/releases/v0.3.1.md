# Treasure Up v0.3.1

首个 GitHub 技术预览版。服务端由 Docker 负责采集、存储、分发和备份；各端客户端连接同一服务，沿用网站登录和播放能力。

## 下载与部署

| 文件 | 用途 |
| --- | --- |
| `treasure-up-v0.3.1-source.zip` | 完整源码和 Docker 部署文件，解压后执行 `python deploy/start.py`；资源有限可加 `--light` |
| `treasure-up-v0.3.1-windows-x64-unsigned.exe` | Windows x64 安装程序，未购买代码签名证书 |
| `treasure-up-v0.3.1-macos-arm64-unnotarized.dmg` | Apple Silicon Mac，临时签名，未公证 |
| `treasure-up-v0.3.1-macos-x64-unnotarized.dmg` | Intel Mac，临时签名，未公证 |
| `treasure-up-v0.3.1-android-arm64-debug.apk` | Android ARM64 调试包，用于预览测试；签名不是长期分发密钥 |
| `treasure-up-v0.3.1-ios-arm64-simulator.zip` | Apple Silicon 上的 iOS 模拟器应用，不是可安装到 iPhone / iPad 的 IPA |
| `treasure-up.user.js` | Tampermonkey 5+ 浏览器选片助手 |
| `SHA256SUMS` / `manifest.json` | 文件校验、源码提交与构建资产信息 |

源码包不包含预构建 Docker 镜像；首次启动会在本机构建。Python 3.10+ 和 Docker Compose v2 为部署前提。默认网址 `http://localhost:8788`，初始化账号 `admin`，随机密码只在交互式终端首次生成时显示并保存到本机 `.env`。已有部署应保留 `.env` 和数据卷，先备份，再将新源码覆盖到原部署目录后执行启动脚本；不执行 `down -v`。数据库迁移由初始化服务处理。

远程客户端填写服务器的 HTTPS 根地址。iOS / iPadOS 真机包、商店分发、通行密钥设备关联、系统 HDR / 杜比输出仍需开发者签名和对应设备验收，本次不宣称完成 iOS 27 真机适配。Android 壳使用播放器的网页全屏；已按锁定 WebView 实现隐藏不可用的系统全屏入口。

## 本版功能

- 视频、收藏夹、UP 主和评论可公开浏览；星标、播放进度与管理操作需要登录。
- 自动备份收藏夹 / UP 投稿，元数据优先归档，下载队列分离，支持授权范围内的充电视频与杜比规格标注。
- 本地 / S3 / OSS 存储、节点同步、无损分片、列表播放、有素材预算的评论、加密备份与恢复。
- 浏览器助手支持视频卡片多选、当前视频、链接批量粘贴、草稿与失败重试；使用可撤销的专用令牌提交到服务端。

## 本次修复

- 退出或切换账号后重新加载页面状态；旧会话迟到的响应不能污染新用户页面或清掉新登录。暂时的鉴权错误可以重试，API 响应不进入浏览器缓存。
- 完整 / 轻量部署切换时，确认新 Worker 的本节点及所需队列均已就绪，再停止旧 Worker。
- 初始化正确归一化 HTTPS 默认端口，拒绝非法站点地址与端口，避免通行密钥 Origin 配置错位。
- S3 / OSS 分段上传检查点失效时，仅对明确的 `NoSuchUpload` 重建一次上传；保留其它错误，避免权限或网络问题被误判。
- 原生连接页初始化不再覆盖正在输入的地址；旧连接的超时回调不能关闭刚建立的新连接。
- 构建工具 Action 固定到提交；发布必须通过应用测试和五个原生目标构建，核对应用版本、实际安装包及 SHA-256，准备完整资产后才公开 Release。

## 已知边界

本次 npm / PyPI 公告扫描未命中已知漏洞。Cargo 锁仍包含 Linux / BSD GTK 链的 `glib 0.18.5`（[RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html)）和 `proc-macro-error 1.0.4`（[停止维护公告](https://rustsec.org/advisories/RUSTSEC-2024-0370.html)）；现有四类客户端目标不使用该链，本版不发布 Linux 原生包。公告扫描不等于所有代码或容器系统包均无漏洞。

云端上传恢复使用 SDK 桩回归，未对真实 S3 / OSS 桶做破坏性试验。原生平台编译通过不替代真机播放和登录验收；客户端清除登录数据的完成时点仍由系统 WebView 决定。跨浏览器标签更换账号后，其他标签在下次鉴权或刷新时更新。超大弹幕交付等既有限制见审计与运维说明。
