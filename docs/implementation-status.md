# 0.2 实施与验收记录

日期：2026-10-04。本文记录实际实现和验收边界；技术计划中的目标不自动等于已验收功能。

## 本轮实现

| 范围 | 当前行为 |
| --- | --- |
| 页面 | 白底紧凑布局、全局搜索、视频播放器 / UP 资料侧栏 / 评论、UP 作品页、后台分区；无伪造推荐、粉丝或统计数字 |
| 播放 | 原档优先；后台生成原码流 fMP4 HLS，按需分片加载、限制缓冲；原档、分片与可选兼容转码分别保存 |
| 杜比 | 从可访问流选择 DV / Dolby 音轨候选；原码流合并保留 DOVI 配置与色彩信息；DOVI/RPU 和 E-AC-3 JOC 验证，记录音视频 packet SHA-256 |
| 音量 | FFmpeg 离线响度分析；浏览器可选增益衰减；不改原始音频文件；多声道与杜比保守旁路 |
| 节奏 | 持久化账号请求 / 视频间隔、随机间隔、风险冷却；下载分片默认并发 1；等待账号冷却不耗失败重试次数 |
| 统计 | 按配置小时刷新已保存视频的播放、赞、币、收藏、分享、评论和弹幕计数及观察时间；可选更新弹幕内容，不重新下载媒体 |
| 多存储 | 本地 / S3 / OSS；按视频同步完整依赖；副本停用、恢复及明确确认后的物理清理；拒绝删除最后一个可用副本 |
| 选路 | 完整副本参与；当前用户浏览器限额测速，综合延迟和吞吐；会话稳定选路、有限故障切换，云端按请求重签名 |
| 权限与备份 | 所有清单 / 分片鉴权，资产会话归属检查；原有 PostgreSQL 一致快照加密备份；恢复撤销旧登录与播放会话 |
| 弹幕 | 保留滚动 / 顶部 / 底部、字体、大小、字重、描边、区域、速度等显示设置；按小云要求取消语义审核，不部署任何模型 |

上一版的评论树、人物快照、独立 Creator 表、收藏关系、标注、任务检查点、租约和旧 Worker 提交隔离继续保留。

## 验收方法

- API 测试覆盖原档选择、HLS 清单、会话归属和过期、私有 Range、限额测速和测量隔离、统计任务以及后台副本操作。
- 存储测试覆盖完整节点选择、固定会话、故障切换、同步依赖、停用恢复、最后副本保护、别名保护及物理清理失败处理。
- 采集测试覆盖杜比候选、真实 DOVI / JOC 证据、请求与视频间隔持久化、重试等待及统计快照幂等；网络响应使用脱敏夹具。
- 合成 H.264 / AAC 视频验证无损 HLS 音视频数据包哈希和可解码性；响度分析后原档 SHA-256 不变。
- 用户提供 ZIP 中两条明确的杜比媒体样本仅用于本机离线验收；原码流合并前后音视频 packet SHA-256 一致。样本及 ZIP 不进入仓库。未执行压缩包代码，未读取或使用其中凭据。
- PostgreSQL 隔离测试验证已有 0.1 媒体记录升级、快照一致性、独立空库恢复、恢复媒体完整解码和旧会话撤销。只操作随机 treasure_test_* 库与测试目录。

最后备份恢复补丁之前的完整回归：Windows **144 通过、13 跳过**；Docker 开启 PostgreSQL 验证后 **155 通过、2 跳过**。两个需显式提供私人媒体样本的杜比用例另外在同一被测镜像中以禁网、样本只读方式执行，**2 项均通过**。Windows 的额外跳过涉及宿主 FFmpeg、符号链接权限和显式 PostgreSQL 条件。CI 使用仓库 `.github/workflows/verify.yml` 的 Docker 测试链，不包含私人杜比样本；最后补丁新增一个恢复参数化用例，定向补测结果见下文。

浏览器已用既有真实视频验证 HLS 起播（1080×1920、427 条已保存弹幕）、进度恢复、手动节点切换、音量平衡切换、弹幕字体 / 区域及恢复默认、UP 作品检索、后台副本列表。公开无凭据接口补齐该样本封面、UP 头像及当前统计，未重新下载音视频。升级前已创建并完整校验本机加密备份。

复核补充了存储写入 / 同步 / 删除的跨提交互斥及真实 PostgreSQL 并发复现，避免已删除对象重新登记为可用。维护任务改为每批 100 条的持久游标，配合索引与批量查重；手动统计批次可由调度器继续完成。配置 PATCH 支持显式清空下载限速。

最后补充验证：当前版与 v0.1 的真实 PostgreSQL 备份恢复 **2 项通过**，SQLite 恢复兼容 **7 项通过**。旧备份仅在指定的空目标库中升级结构，源测试库已删除，防止误用源连接仍能通过测试；恢复后清除未完成调度批次并关闭自动统计与媒体处理。桌面与 390 像素窄屏已复查，默认配置保存成功；原画质标签按横竖视频的实际短边显示。

## 边界

| 项目 | 当前限制 |
| --- | --- |
| 在线采集 | 本轮未使用真实 Cookie 发起新一轮采集；会员实际可用流、评论游标与平台风控需低频小样本验收。间隔设置不能保证永不风控 |
| 真实云桶 | 尚无本轮 S3 / OSS 实桶验收；跨域、签名续期、版本清理、multipart 恢复和费用需在独立测试 prefix 验证 |
| 杜比播放 | 归档媒体证据不等于硬件输出认证；浏览器、系统、显示器和音频设备必须具备相应解码与输出能力。未经验证的 HDR 到 SDR 色调映射不自动执行 |
| 带宽 | 无损分片不降低完整观看时的原码率；节省主要来自按需加载、缓存与减少拖动时的冗余流量。额外分片会占用存储，无实测百分比承诺 |
| 音量平衡 | 只衰减偏响音轨，保持原档；不增强安静素材、不做动态压缩；旁路空间音频，不声称空间输出验收 |
| 云版本删除 | 无明确版本 ID 时，DELETE 可能仅形成删除标记，不能保证历史版本物理占用回收 |
| 备份 | 目的地仍为目录 / 挂载 NAS；默认本机卷不是异机容灾。retention_days 不自动触发删除；未实现原生 S3 / OSS 备份仓库 |
| 规模与上线 | 未做万条视频压测、长期运行验收、跨浏览器 HDR 验收或公网渗透测试。公网 HTTPS 和数据库最小权限需独立部署验收 |
| 完整性 | 只归档平台当前允许访问的数据；不恢复不可访问的已删除内容，不推断用户真实姓名 |

## 技术依据

- [FFmpeg stream copy](https://ffmpeg.org/ffmpeg.html#Streamcopy) 与 [HLS muxer](https://ffmpeg.org/ffmpeg-formats.html#hls-2)：复制压缩流、fMP4、关键帧分段边界。
- [FFmpeg loudnorm](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)：响度测量；项目保留原档，播放时只应用衰减。
- [hls.js API](https://github.com/video-dev/hls.js/blob/master/docs/API.md)：MSE 播放、有限缓冲与错误处理；支持设备可走原生 HLS。
- [采集与杜比验证来源](../backend/app/ingest/SOURCES.md)：yt-dlp、FFmpeg DOVI/JOC 元数据、参考 ZIP 的使用方式和实测边界。

项目独立实现页面布局与归档逻辑，未复制 B 站闭源播放器代码。依赖分别遵循其许可。
