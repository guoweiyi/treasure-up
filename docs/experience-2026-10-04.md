# 浏览、采集和播放器迭代

本次在 0.3 技术预览上改进访客浏览、来源选择、采集调度和播放器，不新增模型服务。

## 可见行为

- 首页、UP 主页、收藏夹、评论、弹幕及视频播放对访客开放。星标与观看进度属于登录用户；后台继续按角色鉴权。访客播放会话绑定短期浏览器 Cookie，不写入全局节点测速记录。
- 收藏夹和 UP 来源沿用源站名称，手工改名保留。添加来源时可以分页选择自己创建的收藏夹、已收藏的收藏夹以及按最常访问排序的关注 UP；链接输入也可解析名称。来源列表只对管理员开放，并有短时缓存、凭据轮换失效、过期响应丢弃及有限重试。
- 视频展示发布时间、联合投稿职责、当前账号探测到的最高可用规格及归档文件码率。没有探测记录就保留空值；这些指标不能推断上传母版或证明平台是否压制过画质。
- 单 P 隐藏选集，多 P 可切换并更新地址。星标按用户独立保存，访客点击后跳转登录。旧共享星标迁移给升级时已有用户，之后互不影响。
- 评论默认按点赞量降序。UP 资料中的有效简介不会再被评论接口里的空简介覆盖；头像保存源站压缩尺寸的 WebP，并以实际响应格式验证。
- 倍速入口靠近弹幕开关；小屏设置使用站内底部面板。弹幕初始速度调慢，底部为控制栏、字幕及安全区留白。已有用户的自定义偏好保留。
- 存储配置、凭据及任务策略改为表单，操作结果以阶段、数量、耗时和探测项目展示。任务详情只在折叠区域保留定位 ID，日常操作不要求填写 JSON。

## 同步阻塞的原因与修正

本机检查发现，原档保存后，兼容转码仍在同一任务里占用采集账号；另有数百张图片逐张等待账号 API 间隔。观察当时账号有效，没有风控冷却。因此本次没有采用增加账号并发或试探封禁阈值的方式提速。

现在 `archive_video` 只负责元数据，基础资料完成后先让出队列；评论、弹幕及图片按处理预算保存检查点。元数据完成后派生 `download_media`，原档保存后派生 `create_playback`。三阶段有各自的任务状态，转码失败不抹去原档。来源重扫识别已派生的下载任务，不覆盖暂停、取消或失败状态。

同一账号的源 API 仍串行，锁仅覆盖实际请求及持久化节奏更新，请求间隔等待在锁外执行，来源选择无需等待整个采集批次。公开 CDN 图片不携带 Cookie，不执行多秒账号等待；媒体传输与本地转码不长期持有账号锁。上游拒绝仍进入冷却，等待锁或视频时段不消耗失败重试次数。标准模式三类 Worker 分离；轻量模式仅合并下载和媒体处理，保留独立采集进程。存储探测使用采集队列，避免排在长时间转码后；既有排队任务由调度器恢复到正确队列。

## 移动端与实现依据

客户端接受站点地址或 `/api/v1` 地址，规范化后连接同一站点。移动播放仍由系统媒体解码能力支持，操作界面、倍速、弹幕和设置由项目提供；没有启用系统默认控制栏。

研究了官方 [ijkplayer](https://github.com/bilibili/ijkplayer)、[flv.js](https://github.com/bilibili/flv.js) 和 [DanmakuFlameMaster](https://github.com/bilibili/DanmakuFlameMaster)。前者是原生播放器，后两者分别是 FLV 转封装与 Android 弹幕引擎，不能直接替代本站的 MP4/HLS 播放路径。参考其解码与交互分离方式，保留当前轻量架构。具体 iOS / Wry 依据见 [播放器说明](../frontend/src/player/IOS_NOTES.md)。

iOS 27 的真机旋转、后台恢复、HDR/空间音频和 WebView 通行密钥仍须设备验收。桌面小屏模拟与 iOS 模拟器构建不能代替这些检查。

## 升级与验证

迁移 `b762ac483f10` 新增个人星标并允许访客播放会话。历史媒体文件不移动、不重编码；旧归档的检查点继续使用。升级命令与分离 Worker 说明见 [运维文档](operations.md)。

回归覆盖访客播放和 Range、个人星标与 CSRF、无权访问后台、浏览器播放会话隔离、真实 PostgreSQL 迁移与并发锁、旧任务恢复、存储凭据保留和换类型清理、来源分页与竞态、播放器边界和备份恢复。真实对象存储桶、未提供的杜比样本及 iOS 27 真机不计作已验收。

本地浏览器验收使用 Windows Chrome 的桌面与 390×844 窄屏，以及应用内浏览器。已实际播放、切换倍速、开关播放器设置和网页全屏，检查访客浏览与登录跳转、个人星标、多 P 选择、联合投稿、码率和评论排序。多 P 和联合投稿采用临时元数据夹具复用既有媒体，验收后清理夹具及派生任务，保留原视频与文件。后台实测来源分页、搜索、选中回填和 Enter 不误提交；存储表单切换类型时清理旧凭据字段。个人账号收藏夹、关注内容和凭据不写入报告。

最终预览验证：关注列表连续加载两页共 48 项，选择后昵称回填正确；创建和收藏的收藏夹各验证了第一页与继续加载入口。先前等待转码队列的本地存储探测已由新队列执行完成，写入、读取信息、完整读取与 SHA-256、范围读取均通过。独立 API 冒烟验证了两个真实归档的访客 Range 播放、跨浏览器会话隔离、后台鉴权和评论排序。最终补丁在新镜像中定向运行来源、访客播放、存储与 PostgreSQL 测试，45 项通过；此前完整后端回归为 337 项通过、2 项环境条件跳过。
